Tune Tournament

What I still make is Tune Tournament shorts, a music-rating series where two songs go head to head and viewers vote on which one sounds better. It's 66 videos deep now, and the thing I'm proudest of is that I don't edit them by hand. I built a generator for it.

It's an idea I had for a while to use code to create YouTube videos. Two raw audio files are inputted, and one finished vertical video comes out. Behind the scenes, it finds the structural sections of each song straight from the raw audio signal, snaps every cut to the beat, picks the most distinct-sounding parts, and loudness-normalizes both songs to the same level. Then, a second stage composites the whole vertical video (tinted from each song's cover art, animated, and captioned) frame by frame.

Namesmith & Brobot

TypeScript, Node.js, Discord.js, SQLite

Namesmith is the project I'm actively working on, and it's built on top of Brobot, the Discord bot. It's a competitive game where players collect characters to craft a username, with mystery boxes, trading, crafting, quests, perks, and ranked-choice voting. I wrote the whole thing in TypeScript with a real CI pipeline (lint, then typecheck, then tests on every push) and kept refactoring whenever the design started slowing me down.

Brobot itself has turned into something I'm proud of despite the years of coding leaving it a little messy. It has 400+ source files and several games/services living in it. A few fun decisions I made with this project were having a typed event system to avoid game logic reaching directly into Discord, scaffolding scripts that generate a new service and repository for me, and, to skip paying for hosting at the start, using a private GitHub repo as a JSON database through the GitHub API.

Activity Wheel

React, TypeScript, Vite, IndexedDB, Supabase

I built a spin-the-wheel activity decider that learns what activities you actually enjoy. You spin it, it picks something foryou to do, and you provide feedback (love it, skip it, hate it), and over time your reactions shift the weights so its picks match you better, without you typing in a number. It uses a weight system designed so that nothing ever gets fully buried and nothing gets permanently favored. Originally I built it just for my own use.

It works fully offline in your browser by default and never makes a network call unless you sign in with Google, which moves your data to a private, row-level-secured PostgreSQL database via Supabase.

Flow Focus

React, TypeScript, Zustand, IndexedDB

I got tired of all the task apps I tried and failed tracking things by hand, so I built Flow Focus to only show you one task at a time, the single most important thing right now, and that's it. I mainly used it for myself when I had a ton of competing things to do with different priorities.

To pick what to show, it sorts every task by how much "slack time" each one has (how long you can safely put it off before it becomes impossible to finish on time), and subtracts the hours you'll be asleep from that math. I liked turning a vague idea like "just tell me what to do" into a real web app I actually could use and benefit from.
